# 에어허브 (Air Hub)

전국 17개 시/도 칩을 클릭하면 실시간 미세먼지 농도·등급·예보·건강 행동요령을 확인할 수 있는 반응형 웹 서비스입니다. (`air_hub_PRD.md` 기준 v1.0 구현)

## 시작하기

1. 의존성 설치
   ```bash
   npm install
   ```
2. 환경변수 설정
   ```bash
   cp .env.local.example .env.local
   ```
   `.env.local`을 열어 공공데이터포털(data.go.kr)에서 발급받은 에어코리아 서비스키(Encoding 키)를 `AIRKOREA_SERVICE_KEY`에 입력합니다.
3. 개발 서버 실행
   ```bash
   npm run dev
   ```
   브라우저에서 http://localhost:3000 접속

## 주요 기능

- 17개 시/도 칩 리스트 (즐겨찾기 최대 5개, `localStorage` 저장 / 최근 조회 도시 자동 복원)
- PM10 / PM2.5 실시간 농도 + 통합대기환경등급 배지 (색상 + 텍스트 병기)
- 오늘/내일/모레 대기질 예보 + 예보 총평·발표 시각
- 등급별 건강 행동요령
- API 실패 시 마지막 성공 데이터 + "갱신 지연 중" 표시, 캐시조차 없으면 에러 UI + 재시도 버튼
- 360px ~ 1920px 반응형 레이아웃

## 데이터 처리 규칙

- **시/도 대표값 = 관내 전 측정소 평균.** 측정소 한 곳(예: 강남구)을 서울 전체 값으로 쓰지 않습니다.
  화면에 평균 산출에 쓰인 측정소 수를 함께 표기합니다.
- **결측 처리.** `pm10Flag`/`pm25Flag`(점검·통신장애 등)가 있는 측정소 값은 평균에서 제외하며,
  값이 전혀 없으면 `0`이 아니라 "측정 데이터 없음"으로 명시합니다.
- **등급 산정.** PRD 9.1 CAI 기준으로 PM10/PM2.5 등급을 각각 매기고, 종합등급은 둘 중 나쁜 쪽을 채택합니다.
- **예보 권역 매핑.** 예보 API(`informGrade`)는 일부 시/도를 권역으로 나눠 발표합니다
  (강원 → 영서/영동, 경기 → 경기남부/경기북부). 해당 시/도는 권역 등급 중 나쁜 쪽을 대표값으로 씁니다.
- **예보 공백 보완.** 당일 첫 발표(05시) 이전에는 오늘자 조회가 비어 있으므로 전일 발표분으로 보완합니다.

## 캐시 / API 호출량 설계

공공데이터포털 개발계정은 일 500회 제한이 있어 사용자 요청과 원천 API 호출을 분리했습니다.

| 대상 | TTL | 비고 |
|---|---|---|
| 실시간 측정치 | 20분 | 원천이 매시 정각 갱신 → 신선도(최대 1시간) 요건 충족 |
| 예보 원문 | 2시간 | 발표는 하루 4회(05/11/17/23시) |

- 캐시는 **메모리 + `data/cache` 파일** 2단으로 저장되어 서버 재시작 후에도 폴백 데이터가 살아 있습니다.
- 예보 원문은 전국 공통이라 시/도별로 재호출하지 않고 `(InformCode, 발표일)` 단위로 1건만 받아 17개 시/도가 공유합니다.
- TTL이 지난 캐시는 버리지 않고 보관하다가, 원천 API 장애 시 `stale: true`로 내려 "갱신 지연 중" 배지와 함께 노출합니다.

### 배치 수집 (권장 운영 방식)

`GET /api/cron/collect` 를 1시간에 한 번 호출하면 17개 시/도 캐시가 미리 채워져, 사용자 요청은 캐시만 읽습니다.

```bash
curl -H "Authorization: Bearer $CRON_SECRET" https://<배포주소>/api/cron/collect
```

- `vercel.json`에 매시 5분 실행 크론이 정의되어 있습니다.
- `CRON_SECRET` 환경변수를 설정하면 해당 토큰이 있는 요청만 수집을 실행합니다. (미설정 시 로컬 개발 편의를 위해 무인증 허용)

## 원천 API 장애 대응

에어코리아 원천 서버는 부하 시 **HTTP 200과 함께** 정상 응답이 아닌 오류 봉투를 반환합니다.

```json
{ "OpenAPI_ServiceResponse": { "cmmMsgHeader": { "errMsg": "SERVICETIMEOUT_ERROR", "returnReasonCode": "05" } } }
```

따라서 `res.ok` 만으로 성공을 판단하지 않고 본문 봉투까지 확인하며,

- 타임아웃 / 네트워크 오류 / 5xx / 위 오류 봉투 → 최대 3회 백오프 재시도 (요청당 8초 타임아웃)
- 인증키·파라미터 오류 등 재시도가 무의미한 코드 → 즉시 실패 처리

로 동작합니다. 재시도까지 모두 실패하면 캐시 폴백 → 그마저 없으면 에러 UI로 이어집니다.

## API

| 엔드포인트 | 설명 |
|---|---|
| `GET /api/air-quality?sido={code}` | 시/도 실시간 PM10·PM2.5 평균 및 등급 |
| `GET /api/air-quality/forecast?sido={code}` | 오늘/내일/모레 예보 등급 및 총평 |
| `GET /api/cron/collect` | 17개 시/도 배치 수집 (캐시 워밍) |

`{code}`는 `lib/sido.ts`의 코드값입니다: `seoul`, `busan`, `daegu`, `incheon`, `gwangju`, `daejeon`, `ulsan`, `sejong`, `gyeonggi`, `gangwon`, `chungbuk`, `chungnam`, `jeonbuk`, `jeonnam`, `gyeongbuk`, `gyeongnam`, `jeju`

## 참고

- 서비스키는 서버(API Route)에서만 사용되며 프론트엔드에 노출되지 않습니다.
- `.env.local`을 설정하지 않으면 API가 명확한 설정 오류 메시지를 반환하며, 프론트는 에러 UI + 재시도 버튼을 정상적으로 표시합니다.
- `sidoName=전국` 일괄 조회는 원천 서버에서 지원되지 않아(항상 SERVICETIMEOUT) 시/도별 호출 + 캐싱 구조를 택했습니다.
